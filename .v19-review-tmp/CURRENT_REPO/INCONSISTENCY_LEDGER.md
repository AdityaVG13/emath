# Inconsistency Ledger

Potential mismatches to resolve empirically during migration:

1. Quickstart declaration spelling versus current EBNF `declaration_head`.
2. Manual Option/Result support statements across capability and standard-library views.
3. Router terminology versus legacy `refused` status rows.
4. Approximate-with-bound label versus ordinary unbounded Float64 execution.
5. Manual capability status versus actual test and provider coverage.
6. Compiler builtin tables versus object-pack/capability-cell long-term authority.
7. Curated-world doctrine versus user-defined-world future plans.
8. “Aliases removed” naming policy versus registered notation/compatibility aliases.
9. Current object identity algorithm versus future public cryptographic identity.
10. Stable and aspirational productions sharing one grammar document.

Every item becomes a correction, accepted distinction, or Spec Hole. V19 does not choose silently.
